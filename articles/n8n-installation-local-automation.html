Installing n8n for
local workflow automation

A practical reference for installing and accessing a self-hosted n8n instance, preserving its configuration, and validating an HTTP webhook before moving a workflow into production.

1. Objective and scope

n8n is a workflow automation platform that connects services and APIs through visual workflows. This guide focuses only on installing and preparing n8n for local testing. It does not cover SIEM deployment or AI-model setup.

The conversation records a running n8n instance reachable at http://192.168.100.225:5678 and a test webhook path of /webhook-test/aiwazuh. Those details establish the intended validation endpoint; the conversation does not record the original installation method, exact n8n version, installation commands, or a confirmed installation failure.

2. Choose an installation method

n8n documents multiple hosting options. For a self-managed Linux host, its documentation recommends Docker for most self-hosting needs and also documents npm-based installation. The current npm documentation states that npm-based installs are deprecated from n8n 3.0 and lists Node.js 20.19 through 24.x for the documented method. Check the official page for the current status before choosing npm.

  • Docker: isolates the application and keeps its state in a named volume.
  • npm: convenient for local experimentation where Node.js is already managed on the host.
Version caveat

The commands below are quick-start examples, not a record of commands run in this environment. For durable or production use, follow the current Docker Compose guide and pin/test a version rather than copying an unversioned setup without a change plan.

3. Docker quick start

Use this example only if Docker is installed and you are starting a fresh n8n instance. The named volume stores n8n data across container recreation. Replace the timezone placeholder with an IANA timezone appropriate for your host.

docker volume create n8n_data

docker run -it --rm \
  --name n8n \
  -p 5678:5678 \
  -e GENERIC_TIMEZONE="Asia/Riyadh" \
  -e TZ="Asia/Riyadh" \
  -e N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true \
  -v n8n_data:/home/node/.n8n \
  n8nio/n8n

Open http://localhost:5678 on the same machine, or use the host's reachable LAN address from another device when networking and firewall rules permit it. This is an interactive foreground example; closing the terminal stops the container. The official Docker Compose installation guide is the recommended starting point for a managed deployment.

4. npm quick start

For a disposable local test, the official documentation describes using npx without a global installation. The documented Node.js version requirements and npm deprecation notice should be checked before using this route.

# Run n8n without a global installation
npx n8n

# Or install globally (check the current docs and Node.js compatibility first)
npm install n8n -g
n8n

After startup, browse to http://localhost:5678. Keep the process manager, service account, update strategy, data directory, and secret management explicit before turning a quick-start process into a long-running service.

5. Access and persistence

  1. Complete the initial setup in the browser and create the instance owner account if prompted.
  2. Record the installed n8n version from the UI or terminal, as well as whether the host uses Docker or npm.
  3. For Docker, confirm a persistent volume is mounted to /home/node/.n8n; do not delete it when recreating the container.
  4. Restrict access to port 5678 to trusted networks and administrators. A LAN address is not a substitute for authentication or transport security.

6. Validate a test webhook with curl

The conversation identifies the following test endpoint:

http://192.168.100.225:5678/webhook-test/aiwazuh

In the n8n editor, create a Webhook node with method POST and path aiwazuh. Start listening for a test event (the button label may differ by version), then send a small JSON request from a machine that can reach the n8n host:

curl -i -X POST \
  'http://192.168.100.225:5678/webhook-test/aiwazuh' \
  -H 'Content-Type: application/json' \
  -d '{"message":"n8n webhook connectivity test","source":"curl"}'

Check the HTTP response and the Webhook node's execution data in the editor. A successful request should reach the waiting test execution; an HTTP response by itself does not prove later nodes or downstream integrations succeeded.

Test URL versus production URL

The /webhook-test/ URL is for editor test executions and requires the test listener to be waiting. For an activated workflow, n8n uses the production webhook URL, normally under /webhook/. Do not move a workflow to production until the request body, error handling, authentication needs, and expected response have been tested.

7. Known issues and troubleshooting

Connection refused or timeout

  • Confirm the n8n process/container is running and listening on port 5678.
  • From the client, verify basic TCP reachability to the host and inspect host firewall rules.
  • When using Docker, verify that the port is published and bound as intended.

Webhook returns “not registered” or does not trigger

  • Confirm the Webhook node's HTTP method and path match the request.
  • For a test URL, click the test/listen control and send the request while the editor is waiting.
  • For a production URL, activate the workflow and use the production URL shown by the node.
  • Check the execution list and response configuration; downstream failures are separate from initial webhook receipt.

Workflow state disappears after container recreation

  • Check that the n8n data directory is backed by a persistent volume or a deliberate host mount.
  • Do not remove the data volume as a troubleshooting shortcut unless you intend to destroy the saved instance state and have a backup.

No n8n installation error or confirmed repair was recorded in this conversation; the items above are diagnostic checks rather than claims about a failure observed in this setup.

8. Security checklist before production

  • Use a persistent data volume and a tested backup/restore procedure.
  • Protect the editor with owner authentication and restrict network access; avoid exposing an unauthenticated instance to the internet.
  • Use HTTPS and the correct externally reachable webhook URL when deploying behind a reverse proxy; configure proxy headers and trusted proxy hops as directed by n8n documentation.
  • Keep n8n, its runtime, and any community nodes updated and reviewed. Run n8n's security audit where available.
  • Use the production webhook only after activating and validating the workflow; do not leave test listeners as the operational plan.
